# Supervising a private qualification study

Use the model-validation skill with the supported runner and continuation
guides. This workflow records an explicitly approved study; it supplies no paid
consent, source exception, deployment or routing authority.

## Before acquisition

Reconcile the private checkpoint with raw journals and actual merged source.
Preserve stopped generations and historical machine results. Recheck complete
reference admission, the fixed sample, each effective request and provider/model
identity, retained source originals and their independently restored backup.
Human feedback applies wherever its reasoning fits the corpus, including cases
already graded. Keep original uncertainty and actor provenance.

Match every declared production fingerprint before claiming old-answer reuse.
Runner-only changes have the existing narrow exception; an adapter repair also
changes a production fingerprint. A successful frozen-generation inspection is
not eligibility on a different source generation. Resolve that discrepancy
before proposing a paid run; do not edit old manifests, silently resample,
drop responses or invent a compatibility approval.

Independently enumerate the full logical schedule and all possible physical
requests. Include historical liabilities, finite replacement allocations,
output/reasoning limits, raw price evidence, framing/margin assumptions and
exact decimal arithmetic. A failed request with unknown billing keeps its
reservation. Raw price annotations may overlap reservations; do not add them as
if they were disjoint invoiced expenses. The operating allowance is not a hard
provider invoice ceiling.

Freeze the actual source, inputs, model/provider pins, fixed study root, plan
hash and exact maximum new count. Obtain actual paid-use consent for that
decision. General process approval, reference approval, synthetic fixtures and a
prior plan hash cannot authorize it. Narrow local key fingerprinting permission
provides no provider-request or account-change authority.

## Launch and supervise

Use normal resource admission and wait when it refuses admission. Keep checks
sequential within the owner's approved envelope. Run the CLI in a fresh,
dedicated serial interpreter with explicit disk scratch; never boot the serving
runtime from a worktree. Keeping a preparation interpreter with the SDK loaded
beside another SDK CLI counts both working sets against the whole-job cap. Use
separate preparation and actual CLI phases or a small standard-library-only
supervisor.

For a durable approved acquisition, use a transient user service with effective
Type=exec, MemoryMax=1G, MemorySwapMax=0 and CPUQuota=50%, through the normal
resource procedure. Collect the unit afterward. Record its actual name, command
source, PID, cgroup, start/exit and effective properties; a launcher returning
success is not a completion receipt. Keep secrets out of command-line and
metadata records. Use the approved existing credential-selection path.

Budget file descriptors before launch: journal and frozen-input readers retain
them. Include the complete history/owner/input census, `max_new_attempts` and
measured runtime headroom. Set the transient unit's `LimitNOFILE=soft:hard`
within the user manager's existing hard limit, then verify
`resource.getrlimit(resource.RLIMIT_NOFILE)` in the actual service child and
exercise harmless high-descriptor event-loop I/O. A scope inherits its caller's
limits; a service applies manager defaults, so a successful scope run does not
establish service capacity. Do not change persistent manager limits. See
[systemd-run](https://www.freedesktop.org/software/systemd/man/latest/systemd-run.html)
and [systemd.exec](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html).

Leave the plan-bound `study_root` absent for the controller to create exclusively.
Put outer launch metadata beside the study evidence, not in a precreated study
directory. An existing root or partial generation prevents relaunch. Confirm
actual unit/cgroup and evidence state after a tool interruption before taking
another action. Cancel only the owned invocation and preserve all evidence.

Do not impose a backup job's runtime limit on the full study. Legitimate model
latency can make the complete schedule long; any new overall limit requires its
own justified decision. This workflow adds no persistent daemon, timer,
bootstrap activation or deployment.

The bounded plan permits only its precise complete upstream-pool rejection to
advance to a separately funded physical replacement. An inherited rejection
already consumes its replacement slot. Close the failed writer before waiting
the declared cooldown and checking admission again. Timeout, partial response,
unknown observation, conflicting billing/identity, cleanup failure, exhausted
caps and repeated rejection stop acquisition. Malformed grades stay measured
errors and stop later acquisition; they are not replacement opportunities.

## Read the actual outcome

Inspect using `study-check` and `study-report` with every admission input. Active
writers are busy. Missing or invalid closure cannot certify reuse; readable
physical costs remain visible. Unreadable evidence leaves the affected census
unknown. A partial terminal, an exited unit or a successful replacement never
clears an unresolved reservation or recreates a lost answer.

Keep model quality, logical completion, operational failures, financial
completeness and closure separate. Report all case/class/repetition denominators,
observed errors, physical dispatches and GETs, identities, actual costs and
remaining uncertainty. A sampled incumbent remains a baseline, with full
qualification not assessed. Repeated answers do not create independent cases.
An inconclusive result is valid.

Synthetic oracle labels, deterministic embeddings, extraction stubs and mock HTTP
demonstrate integration. They establish neither actual model accuracy nor real
retrieval/extraction quality. Four disposable storage modes exercise current and
hypothetical promoted behavior; the latter does not approve promotion.

Retain plan, real consent, source/input hashes, original and child journals,
terminal/partial closure, report and unit receipts. Independently reconcile
reported numbers with their raw denominators. Verify the exact irreplaceable
packet's encrypted backup inclusion and an isolated restored hash census. A
packet restore is not a whole-system recovery claim. Use the authorized validator
for verification obligations; an external client's build does not grant
lifecycle enrollment or verification-write authority.
