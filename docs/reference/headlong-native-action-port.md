# Contained native action-port qualification

This developer experiment runs real Claude Code through public
`ClaudeSDKClient`, pinned SDK 0.2.172, inside disposable CI. A loopback fake
Anthropic Messages backend scripts the model responses. No real inference,
account, credentials, production state or runtime provider is used. It builds on
the [stock controls](headlong-offline-controls.md); stock text-route results
remain a separate denominator. This port is a foundation for B/C, not their
orchestration implementation or an adoption decision.

The image adds only committed Genesis source and license to its archive build
context. It imports the actual canonical proposal CRUD and two schema declarations
without application initialization or migrations. A separate container uses the
same nonroot, read-only, loopback-only, mount-free, capability-free resource
boundary as the stock controls. Preflight runs before native code or dummy-key
injection. The bundled native binary is selected explicitly; its version and
hash, SDK/dependency inventory, Genesis commit and source/helper/DDL hashes are
recorded. Every child gets fresh HOME, working directory, database and session.

Native settings explicitly select the Claude Code system preset, no inherited
settings, strict MCP configuration, no built-in tools, `dontAsk` permissions and
only `mcp__fixture__claim_effect` allowed. The one SDK MCP tool accepts a proposal
ID only. Its ordinary async handler owns the connection and fixed effect path;
it rejects foreign nonnull sources, honors legacy null sources, invokes actual
`claim_proposal_for_dispatch(allow_develop=False)`, and writes fixed bytes only
after a true claim. Its disposable sink appends fixed bytes, so accidental replay
changes the artifact even if both writes contain identical bytes. Owner setup uses canonical create/resolve/revoke outside the
model. Permission callbacks and model statements never grant owner authority.

The exact population is eleven: echo calibration, approved, pending, rejected,
revoked, develop, duplicate, foreign source, legacy null source/scope, unknown ID,
and provider error. A failed echo immediately stops the run as incomplete. Normal
cells require a typed successful native Result and exact scripted final, observed
API requests, expected native tool-result IDs, actual handler dispositions,
independently read committed state and exact file bytes. Duplicate requires two
real canonical calls with one true and one false claim. Provider error requires
an observed synthetic API error and native error result, with no tool/effect;
startup or transport failure cannot pass that control.

The pinned SDK catches handler exceptions and can later finish a turn successfully.
The handler therefore records exceptions out of band, and the qualifier returns
incomplete regardless of successful final text. A separately counted instrument
control deliberately raises in the handler and requires a successful native final
to be rejected as incomplete. It is not a twelfth passing policy cell. SQL or
file errors, missing evidence and uncertain effects are never normalized into
policy refusal. A committed claim without an effect is incomplete and is not
replayed. The SDK wrapper at this pin reads `is_error` on tool handler returns;
independent checks do not rely on that flag.

The portable boundary is the MCP/JSON work-tool contract; SDK registration and
engine lifecycle remain provider-specific. This does not implement the complete
production `AgentProvider` contract, cross-engine resume, Codex parity, built-in
adversarial-tool coverage, initiative/feedback/recovery parity, or real model
quality. Those require the remaining comparison matrix. Canonical source binding
here is tested on immutable fixture rows; concurrent source mutation and
generation fencing remain unqualified.

The workflow reruns all stock controls before native qualification, retains
reports and actual container/image metadata for seven days, and removes only the
run's named containers even on failure. A separate
[monolith/native probe](headlong-native-monolith.md) follows this phase.
A timeout/killed job cannot produce a passing
report. Host-safe tests cover actual CRUD and evaluator faults without executing
native code; native execution is exclusively in disposable CI. Full integration
is unqualified until the exact-head contained report is observed after review.
