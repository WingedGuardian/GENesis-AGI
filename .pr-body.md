Fixes #4856

## What and why
Answering "what was said on day X" from transcripts that live on a remote edge device took a session more than ten SSH round trips. That was measured once at 5m47s before the lines were in hand. No tool read that store.

## How
A new `edge_transcripts(action, date, query, max_lines)` tool on the health MCP:
- `status`: total files, the latest file, and the files on a day.
- `list`: one local day's files.
- `search`: fixed-string, case-insensitive matches with two lines of context.

Configuration:
- Set `transcripts_dir` in `ambient_remote.yaml`. There is no default; without it the tool reports "not configured".
- Files are named by UTC start time (`YYYYMMDDTHHMMSS….md`).
- A day is the user's local day (`user_timezone()`), which can span two UTC dates.

**One remote pass per call:** `find -H <dir>/ -maxdepth 1 -type f \( -name '<D1>*.md' -o -name '<D2>*.md' \) [-printf … | -exec grep -F -i -n -H -C 2 -e <q> -- {} +] | head -c 262144`.
- `-H` follows a symlinked directory but never a symlinked file, so there is no list-then-read race.
- The edge filters by date, so a growing directory cannot push the day out of the listing.

**Command safety:**
- The date is checked by full match.
- The query is `shlex.quote`d after `-e` and `--`.
- The directory must be an absolute or `~/` path; `~/` stays expandable as `"$HOME"/…`.
- `test -d` guards the pass, and any exit outside {0, 1} is an error, never an empty day.
- Output is capped remotely and at `max_lines` (≤ 500), with a `truncated` note.

**Who can call it:**
- Every dispatch profile that ingests outside content or can send outward is denied: interact/sentinel, research, campaign, community-responder and mail. Read-only `observe` keeps it.
- Reflection sessions don't get it (it is not on their read allowlist).
- External profiles don't get it (it is not in `HEALTH_FLOOR_TOOLS`).

Nothing is copied into Genesis by the tool. The lines it returns do land in the calling session's transcript and its backups, as a manual read of the same files would; the docstring says so.

Pre-existing, not changed here:
- The unauthenticated OpenClaw chat gateway gets the full tool set.
- `_ssh_base` does not guard a `host_user` value that starts with `-` (that needs config write access).

## Testing
- **Tests:** 275 passed across `test_edge_transcripts.py` (22 new), `test_direct_session_profiles.py` (new profile test), `test_reflection_tool_scope.py` and `test_health_mcp.py`. The new tests cover:
  - the UTC/local day boundary;
  - a query injection corpus parsed back with `shlex`;
  - refused directories;
  - error codes 124, 3 and 255 on every action;
  - capping and day filtering of grep lines.
- **Live, read-only, from this branch's module** (counts only, nothing stored):

  | Call | Result | Time |
  |---|---|---|
  | `status` | 102 files | 1.1 s |
  | `list` for a past day | 5 files | 0.4 s |
  | `search` | capped at 20 lines, marked truncated | 0.6 s |
  | `search`, no-hit query | 0 matches | 0.5 s |
  | `list`, missing directory | the directory error | — |

- **Review:** a security review (genesis-security-reviewer) found 1 critical (profile reach) and 5 warnings. All are fixed, or stated in the docstring and above.

E2E: after deploy, set `transcripts_dir` in the install's `ambient_remote.yaml` and restart a session. A Telegram question about a past day's transcript then makes one `edge_transcripts` call instead of a chain of SSH commands, and the answer arrives within about a minute of the turn starting.
