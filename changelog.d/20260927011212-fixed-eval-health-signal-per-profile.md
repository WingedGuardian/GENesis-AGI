- **Eval health now reports each model profile separately and separates harness noise from wrong answers.** When a provider was repointed at a new model, `eval_staleness` summed both models' history under one row and labelled it with whichever profile ran last, so its counts described neither. Each `(provider, profile)` now gets its own entry with a `recent` block (last 30 days of that profile's runs) showing the wrong-answer `failure_rate` and the `infra_rate` (rate-limit skips plus provider errors such as timeouts). `unreliable` now fires on the infrastructural share, so a timeout-heavy run is flagged while a reproducible wrong-answer rate is reported as a rate instead. Manual benchmarks (`scheduled: false`) and profiles a provider has moved on from (`superseded: true`) are no longer reported as `stale`, and staleness is measured from the last scheduled run, so a manual run cannot hide a stopped scheduler. `stale_count` and `unreliable_count` now only count profiles that are still scheduled. A failed query now reports `status: error` rather than `no_data`. The dashboard's eval section shows the profile, the recent failure rate, and greys out manual and superseded rows.
