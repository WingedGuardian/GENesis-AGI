- Memory-graph reads now use the FalkorDB graph engine by default wherever it is installed: `config/graphstore.yaml` ships `mode: falkordb`. An install where the engine was never set up, or its `genesis-falkordb` unit is not enabled, keeps reading from the in-process NetworkX projection with no warning and no health alert. `bootstrap.sh` and `install.sh` now enable and start the `genesis-falkordb` unit after setting it up; an engine that is already running is left running, and a start that fails prints one warning without stopping the install. Saving graphstore settings in the dashboard now stores only the settings you changed, so an unrelated save no longer pins `mode`. Once the unit is enabled, or reads are set to the engine, the engine counts toward the critical-failure health signal. The hourly graph projection also runs once five minutes after its timer starts, so a fresh `install.sh` install usually reads from the engine without waiting an hour. Because the settings page shows the stored config, it cannot save `mode: falkordb` explicitly while that is already the shipped value; enable the engine's unit instead. To keep reads off the engine, set `mode: networkx` in `~/.genesis/config/graphstore.local.yaml`; or list `genesis-falkordb.service` in `~/.genesis/config/disabled_timers` and disable the unit, which keeps reads on NetworkX and stops the installers enabling it again.
