- **A killed Guardian tick no longer loses what it was doing, and an approved recovery held back by its backoff still runs.** Before an approved action runs, the Guardian now counts it and saves its state to disk, recording a `live` drop as attempted before the engine call (a clean refusal puts back the record that was there before); if that save fails, nothing runs and one critical alert names the state file. A tick killed mid-action wakes as RECOVERED instead of staying "recovery in progress", and a tick killed before any action leaves the previous tick's state as it was; a cancelled `incus exec` client is killed. An approved action deferred by a backoff of at most 900 s is waited out inside the tick and then run unless Genesis is back or paused, with no second diagnosis or prompt, and a proposal whose own budget is spent (IO_TRIAGE's own counter for IO_TRIAGE) escalates instead of being put to the approval gates. These apply to every install. `deploy_candidates drop` and `rebuild` now remove a harmless leftover `update_state.json` only after the refusals under the checkout lock, so a busy checkout lock keeps it; drop removes it just before its manifest write, so a removal that fails leaves the candidate listed, and a manifest write that then refuses says the leftover went.
