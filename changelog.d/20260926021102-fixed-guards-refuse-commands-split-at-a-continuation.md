- The shared shell parser behind the command guards now reads backslashes, quotes and comments closer to the way the shell does. An escaped character outside quotes (`\;`, `\|`, `\&`, `\"` and the rest) is kept as a literal inside its word, so an escaped quote can no longer hide the commands after it and `find … -exec … \;` is no longer split. A quote or a trailing backslash inside a `#` comment is now literal, so it no longer swallows the next line; a `;` inside a comment still separates, which errs toward refusing. A command containing a heredoc is also read with each heredoc body taken out of the shell code, keeping the command substitutions an unquoted body would run, and where the escape or comment rule touched a quote it is read the older way as well; the commands every reading finds are all checked, so no reading can hide a command another one shows. Escaped backticks and `\$(` are no longer mistaken for command substitutions, a substitution after an apostrophe inside double quotes is now seen, and a backtick substitution nested in another is found. A backslash line continuation is still not joined: the parser records where it sits, including inside double quotes and inside a word, and the git-clean and submodule-recursing checkout blocks, the protected-path guard, the push and merge gate and the commit gate refuse a continued command that names their operation, including inside `bash -c '…'` and `$( … )`. The protected-path refusal applies whichever parsing problem is reported first. The destructive-command guard keeps its own continuation handling and now also finds a removal nested in `$( … )` or backticks when a continuation is present, and a continued commit now clears a stale review marker. The refusal is limited to the command the continuation touched, so a continuation elsewhere in the line, or one in a command that only mentions the word in prose, no longer refuses. `# discard-override` still waives the git-clean and checkout cases when it is written on the continued command itself.
