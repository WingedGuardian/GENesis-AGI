- The shared shell parser behind the command guards now reads backslashes, quotes and comments closer to the way the shell does. An escaped character outside quotes (`\;`, `\|`, `\&`, `\"` and the rest) is kept as a literal inside its word, so an escaped quote can no longer hide the commands after it and `find … -exec … \;` is no longer split. A `#` comment is now literal text, so a quote or a trailing backslash inside one no longer swallows the next line. Because the parser cannot tell shell code from a heredoc body, where the shell reads neither rule, a command in which either rule touched a quote character is also read the older way and the commands both readings find are all checked; neither reading can hide a command the other shows. Escaped backticks and `\$(` are no longer mistaken for command substitutions, a substitution after an apostrophe inside double quotes is now seen, and a backtick substitution nested in another is found. A backslash line continuation is still not joined: the parser records where it sits, including inside double quotes and inside a word, and the git-clean guard, the protected-path guard, the push and merge gate and the commit gate refuse a continued command that names their operation, including inside `bash -c '…'` and `$( … )`. The refusal is limited to the command the continuation touched, so a continuation elsewhere in the line, or one in a command that only mentions the word in prose, no longer refuses. The destructive-command guard keeps using its own continuation handling. `# discard-override` still waives the git-clean case when it is written on the continued command itself.
