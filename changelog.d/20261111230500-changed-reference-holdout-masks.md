- Saving a credential reference never fails, and never drops part of it, because of where its secret appears. Its name and tags are the only parts that are searched: a secret that appears in either is masked there as `[held]` before a long name or tag is cut, and the save goes on. The full name stays recorded with the secret, so a masked or cut name still finds the same entry, and a reply whose stored name differs from the one given ends with ` (stored as: <name>)`. Everything else the caller sent with it (source details, purpose, caveats, and the name and tags as given) is kept with the secret, outside the search index, and is shown when the credential is revealed. An unknown memory class is stored as `fact`, a missing name is given one, and a body whose shape is ambiguous holds more of itself out instead of being refused. Credentials found in an uploaded file or a distilled document are stored as new entries instead of being refused or replacing an existing one; one that cannot be stored is reported in the document's quality notes, and the upload is shown as incomplete. A payment-card number in a credential's name or details is replaced with a marker and never stored. Any reference kind can now hold a value out the same way.
