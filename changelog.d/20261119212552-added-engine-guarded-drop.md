- **The deploy-candidates engine can drop a `live` candidate, confirm it and queue the server restart in one locked step.** `scripts/deploy_candidates drop <branch> --expect-branch live --expect-head <tip> --expect-candidate <pinned head> [--restart-server] --wait 0` refuses with nothing changed when the candidate was re-pinned since it was approved, confirms the drop from the engine's own view before anything restarts, and queues `systemctl --user restart --no-block genesis-server` only then (nothing while a start is already in progress; exit 4 when it cannot be queued, with the drop done). The whole sequence runs under one update.lock hold, so no other writer can land between the steps. `list --json --move-refusals` now also reports the checkout and every reason a move would be refused, and re-adding a candidate at a new head moves it to the end of the manifest. A plain `drop` behaves as before.
