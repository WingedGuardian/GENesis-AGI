- **Bearer-token checks compare the bytes the client sent.** The MCP HTTP transport's auth guard and the dashboard's internal-API bearer check compared the presented token as text, so a token with non-ASCII characters (or header bytes that are not valid UTF-8) raised inside the comparison and the request failed with a 500. Both now compare bytes and refuse a wrong token with 401. The dashboard's bearer checks (`/v1` routes and the internal API) also read the header as the bytes the client sent, so a correctly configured token containing non-ASCII characters is now accepted instead of refused.
