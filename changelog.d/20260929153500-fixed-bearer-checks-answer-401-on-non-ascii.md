- **Bearer-token checks compare the bytes the client sent.** The MCP HTTP transport's auth guard and the dashboard's internal-API bearer check compared the presented token as text, so a token with non-ASCII characters (or header bytes that are not valid UTF-8) raised inside the comparison and the request failed with a 500. Every bearer check now compares bytes and refuses a wrong token with 401. A correctly configured token containing non-ASCII characters is accepted whether the client sends it as UTF-8 or as latin-1 (as Python's `http.client` does); previously the dashboard's `/v1` check accepted only the latin-1 spelling.
