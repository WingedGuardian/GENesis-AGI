- A `git push` or `gh pr create` run from inside a subagent is now refused, with instructions to commit locally and hand the branch back to the main session, which publishes. This covers re-pushes to an existing PR branch too, so a subagent fixing a PR leaves the push to the session that dispatched it. Fanned-out subagents no longer put one approval prompt per agent in front of you. With `hooks.asks.push_publish: off`, a first push spelled `git -C <a worktree of the same repository> push …`, or followed by `2>&1` and a `| tail -N` / `| head -N` output filter, is now silenced like a plain `git push`.
