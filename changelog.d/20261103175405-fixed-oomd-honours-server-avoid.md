- systemd-oomd now monitors the per-user manager, where the Genesis server's "kill me last" preference is honoured: a memory-pressure kill takes a session or background run first and reaches the server only when nothing else is left. Before, a `systemctl --user daemon-reload` (run on every bootstrap and deploy) silently dropped that monitor (systemd issue #43174), leaving only the root-owned `user.slice` monitor, which ignores the preference, so the server was killed like any other process. The per-user limit is 60% of PSI `full` time (overriding the distro's 50%), and `user.slice` stays monitored as a backstop at 80% for pressure the first monitor cannot relieve; both are upstream-aligned starting values, not yet tuned to measured pressure. The user manager itself, its D-Bus, the shared Serena units and the disk guardian are protected too, `bootstrap.sh` reports which monitors are in force, and the awareness loop alerts when the per-user monitor is not live.
