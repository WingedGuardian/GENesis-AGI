- **The worktree reaper no longer archives uncommitted work on the short clock, and `--recover` brings an archived worktree back exactly when it can.**
  A worktree whose branch (or detached HEAD) has no commits of its own passes the "merged" test vacuously, since its tip is already a commit on `main`. While such a worktree holds uncommitted changes it now waits the 14-day unmerged window, and reports as at-risk meanwhile, instead of being archived at 7 days; a clean one still drains at 7 days, and a branch merged through a merge commit keeps the merged clock.
  Archiving already keeps the worktree's git registration, locked as the history anchor. `worktree_lifecycle.py --recover` now moves the archived tree back under that registration when it still belongs to the archive, which restores the tree exactly: tracked edits, the staged/unstaged split, intent-to-add entries and untracked files. The reaper's `.dirty.patch` snapshot, written into the tree at archive time, is left in place and named as safe to delete once checked. An archive whose path was archived again later is refused rather than placed under the newer archive's registration, and a registration that cannot be read stops the recovery with nothing changed.
  When the registration is gone, recovery recreates the worktree at its recorded ref with its untracked files, as before. If the archive held uncommitted changes, that recovery now exits with status 2 and names the kept archive (and the snapshot file, if it came back) instead of reporting success; a legacy trash directory in that state is kept rather than deleted. `--recover --dry-run` says which of the two a real run would take, and that the second would exit 2.
