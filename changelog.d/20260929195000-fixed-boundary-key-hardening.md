- **The content-boundary key no longer affects knowledge caching, is read safely, and is backed up.** The web knowledge processor removes the fetcher's own boundary wrapper (a complete opener and closer with matching ids) before the page text is hashed, so a changed or restored `~/.genesis/boundary_key` no longer makes unchanged pages re-distill; local documents are hashed exactly as they are. The key file is read only if it is a regular file no larger than a key, without blocking; anything else falls back to a per-process key with a warning. The encrypted backup now includes the key (honouring `GENESIS_HOME`), and restore stages it with the other credential files. Web pages already in the knowledge base re-distill once on their next re-ingest, as they would after #2537's wrapper change in any case.
