- **The Guardian's recovery brain can now authenticate when the host login is not confirmed, and says why when it cannot.** It used to inject the synced setup-token only when `claude auth status` explicitly reported the login dead. On a host with no working login, a pre-flight that timed out or answered unclearly (for example right after a host reboot) left the brain unauthenticated, and the Guardian could only page "all automated recovery failed". It now uses the token unless the login is confirmed working. When a diagnosis run fails, the page and log carry Claude Code's own reason (it reports failures in its stdout JSON, which was being discarded), and the work dir gets the empty MCP config it expects, so the brain no longer loads MCP servers it does not need.
