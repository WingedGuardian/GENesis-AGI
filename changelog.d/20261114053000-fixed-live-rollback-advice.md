- **A `live` update stopped after its merge step now gets advice that fits it.** When an update on the `live` branch failed or was killed during bootstrap, migrations or the health check, the messages read as if it were a normal update on `main`: "finish it with `update.sh --post-merge`", and, for a half-restored checkout, "code bootstrap never ran on", which is false there. They now say what happened (it was killed in that phase, or it failed and may have been rolling back), that nothing finishes that rollback automatically yet, and that `--post-merge` only retries the same code and keeps a migrated database if it rolls back again. A checkout already back at the rollback tag is told the rollback may not have finished and to dismiss the update and run it again, instead of "put the checkout where you want it". The verdicts and exit codes are unchanged.
