- **The worktree reaper no longer mistakes a recently changed worktree for an idle one.** Its activity clock missed several kinds of change below its shallow scan: a file or folder deleted or renamed deep in the tree, a path git quotes because it holds unusual bytes, an edit inside a submodule, and a commit, whose status is clean afterwards. It also archived a worktree changed while the scan was running. The clock now reads three signals, one for each kind of change: every directory's mtime (anything created, deleted or renamed, at any depth), the paths git reports as changed (edits), and when HEAD last moved, read from the timestamp inside the reflog's last entry, which `git gc` leaves intact. Right before archiving, the reaper re-checks the age and compares the worktree's HEAD and status with what it read at classification, and holds the worktree if anything changed or cannot be read. A worktree it holds no longer stays listed for archiving on the board until the next run.
