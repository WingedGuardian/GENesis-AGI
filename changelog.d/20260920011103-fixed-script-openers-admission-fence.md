- Database connections now refuse a database that is quarantined **or** held for maintenance, at every place one is opened. Previously the central connection factories checked quarantine only, several opened nothing-checked at all, and script-side hooks consulted nothing — the path by which hook writers kept writing to a database already marked corrupt during the 2026-09-18 incident. A syscall-level replay of all 17 automatic entry points (every CC hook, both session-boundary workers, the timer-driven maintenance jobs, and the post-commit git hook) now measures zero opens of a fenced database, with an unfenced control proving each probe can still tell the difference.
- Fixed a post-commit hook regression in the same area: the audit helper git installs into `.git/hooks` could not import its new fence dependency from there, so every `fix:` commit silently skipped recording its audit observation. The helper's dependency is now installed alongside it.
- The read-only connection path, the standalone short-lived path, session peer-awareness reads, and session-start procedure injection are all fenced for the first time; a read-only handle still holds a descriptor on a database an operator is trying to replace.
- Added a structural gate so this cannot quietly regress: the set of connection-opening functions is now enumerated by AST and each must assert admission, and a second gate covers `scripts/`. Adding a new way to open the database fails the build until it is classified. Operator-run command-line tools remain deliberately unfenced — a human is present, and some of them exist to inspect a database precisely because it is suspect.
