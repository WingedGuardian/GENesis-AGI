- **A failed update no longer throws away uncommitted edits made while it ran.** If another session or editor changed tracked files after `update.sh` merged, and a later step failed, the rollback's `git reset --hard` discarded those edits; only `AGENTS.md` and `config/procedure_triggers.yaml` were saved. The rollback now uses `git reset --keep`, which leaves every edit to a file the update did not change in place, and refuses outright when a file the update changed has local changes. In that case it reports the update as not rolled back and keeps the migrated database to match the code left in place. Before the reset it records the checkout's uncommitted changes, staged state included, as `refs/genesis/rollback-save/<time>-<pid>`, restorable with the printed `git stash apply --index <sha>`; the daily disk hygiene prunes these refs after 45 days. It also refuses when the reset would overwrite an untracked or ignored file.
