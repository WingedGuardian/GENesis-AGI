- **The backup warning now says which extra directory was only partly backed up, and a Python virtualenv no longer causes it.** When a directory listed in `GENESIS_BACKUP_EXTRA_DIRS` held members a restore would refuse, the dashboard said only that "some configured extra directories were not fully backed up" and pointed at the log. The status file now records each partial directory with the count of refused members by reason, and the dashboard's backup warning names them for a signed-in operator. The unauthenticated status route still shows only the generic text. A virtualenv's `bin/python*` interpreter links are absolute, so a restore refuses them, which made any directory holding a venv report partial unless the venv was named exactly `.venv` or `venv`. Those links are now left out of the archive for any virtualenv, found by its `pyvenv.cfg`, and the rest of the venv is still backed up.
