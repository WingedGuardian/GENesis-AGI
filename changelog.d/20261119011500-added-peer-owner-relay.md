- **A same-owner agent peer can relay the owner's own requests.** Before this, every peer session was told that peer content is never owner approval, so a request the owner gave their own agent to pass on was refused. A new per-peer grant, `owner_relay` (`genesis peers grant <peer> owner_relay allow`), tells that peer's sessions that a relayed owner request is the owner's request. Money, destructive actions and approving an autonomous session still need the owner directly. When a relayed session uses any tool outside a short read-only set, or may have (a partial record, a restart), the owner gets one Telegram alert naming the tools and quoting the session's summary. Without the grant nothing changes. Every peer session is now also told to look a name, address or fact up in memory and references before refusing because it does not match.
