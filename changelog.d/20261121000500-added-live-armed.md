- The `live` deploy engine is armed. Its readiness marker, `scripts/lib/deploy_live.sh`, now exists, so once a deploy puts that file in the server's base, `scripts/deploy_candidates add` and `rebuild` can run candidates on `live`. Where a host guardian is configured, readiness also requires the deployed commit that the last host probe recorded to carry the host guardian's `live` ban (#3546). If that probe is missing, unreadable or does not resolve to a commit, readiness names the problem instead of passing. Until the Guardian can drop a candidate itself, a candidate that keeps the server down must be removed by hand with `scripts/deploy_candidates drop <branch> --wait 0`.
