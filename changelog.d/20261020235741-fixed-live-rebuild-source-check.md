- **A `live` rebuild refuses to move a checkout someone changed while it was planning.** The rebuild now records where the checkout was (its branch, commit and a clean tracked tree) before it fetches, and checks it again once it holds the checkout lock and just before it writes anything. A commit, branch switch or tracked edit made in that window makes the rebuild refuse with nothing moved, and `update.sh` rolls back as for any other refusal, instead of resetting `live` over the commit or moving the checkout off the other branch. `update.sh` passes the branch and commit it verified (`rebuild --expect-branch --expect-head`). A commit that lands in the last moment before the switch is still possible; the rebuild then prints a warning naming it, and it stays in the `live` reflog. A tracked edit made in that same last moment is not warned about. Rebuilding `live` is still disabled on every install until the remaining safeguards land.
