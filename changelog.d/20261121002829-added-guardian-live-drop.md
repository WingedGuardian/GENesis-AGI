- **The Guardian can drop the newest `live` candidate itself, behind an off-by-default switch.** With `recovery.live_engine: true` in the Guardian's config, an approved code revert on a `live` checkout becomes the drop of the newest candidate, named at the action-approval step together with every other candidate it takes out of `live` (the engine refuses the drop, nothing changed, if that set has changed), run as one call to the engine's guarded drop, and judged done only once genesis-server has booted from `live`'s new tip. A drop that did not finish becomes an escalation that names `deploy_candidates rebuild`, and a drop whose outcome was not seen is named in the next diagnosis. With the switch off (the default) nothing changes.
