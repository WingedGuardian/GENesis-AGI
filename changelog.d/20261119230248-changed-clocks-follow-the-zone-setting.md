- **The system clocks now follow the zone setting.** A new daily job (`genesis-tz-align.timer`, 12:20 local) and every change of the dashboard's Timezone control set the host clock (through the guardian gateway) and the container clock to the zone in `genesis.yaml`; without a guardian only the container clock is set, when passwordless sudo is available. An install that never chose a zone is left alone: the shipped `UTC` placeholder counts as a choice only once it is picked on the dashboard. **Existing installs whose clocks differ from the setting are moved at the first midday run after updating.** Host jobs (package updates, log rotation, fstrim, cron lines) then run at their usual times in local time, as on a fresh install, and at that first move each daily or weekly host job whose new local time falls between its last run and the move runs once. Re-picking the zone already chosen does nothing, and a host move to a different zone waits 60 minutes after the last one, because each move can re-run daily host jobs. Turn it off with the `tz_align` setting (`mode: off`) or `GENESIS_TZ_ALIGN_DISABLED=1`, which stop both the timer and the dashboard path. To stop only the timer, run `systemctl --user disable --now genesis-tz-align.timer` and add a `genesis-tz-align.timer` line to `~/.genesis/config/disabled_timers` so the next update leaves it off.
