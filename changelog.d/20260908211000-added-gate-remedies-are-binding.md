- **A blocking gate's enumerated remedies are now mechanically binding.** When a
  gate stops you and lists the ways forward, that list is the option set — and the
  agent relaying it to you is the weakest point. Measured: a review cap printed
  three remedies and the relay dropped the first, invented a fourth, and added the
  one outcome the cap exists to prevent. The gate's own text was one message
  earlier, so nothing had been forgotten; a strong prior simply beat what was on
  screen, which is why showing the text again is not the fix.

  The remedy set is now written down as data rather than living only in prose.
  While a decision is outstanding, a question put to you is refused unless it
  offers exactly those remedies, and the acknowledgment that closes the decision
  has to name which one was chosen. The block message prints the exact command for
  each remedy, so a bookkeeping failure never quietly downgrades to accepting an
  unnamed acknowledgment.

  The check that decides whether a question really offers the remedies is a
  bijection: that question's options are the remedy set, one each, nothing else.
  Three counting rules were defeated before it, each narrower than the last, and
  the reason is structural — the relaying agent writes the option text, so no
  count over those words closes the gap. The last of them still passed the case
  this exists for, because a test that asks whether the remedies are *present*
  cannot see an option that was *added*, and an added "ship as-is" beside three
  genuine remedies is the original failure almost verbatim.

  There is deliberately no "proceed as-is" escape. Accepting the findings as they
  stand is what the final round offers, several rounds later; withholding it here
  is what this stop is for. An earlier version added one, checked against the
  session transcript, and it was removed rather than repaired — the evidence could
  not support the claim, since the check never read which option you actually
  chose.

  A decision records the session that owes it, so one session's outstanding
  question is never put to, or closed by, another.
