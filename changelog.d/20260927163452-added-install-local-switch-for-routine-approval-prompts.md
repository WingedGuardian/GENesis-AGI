- **An install can now switch off two routine approval prompts without loosening any block.** `hooks.asks` in `~/.genesis/config/genesis.yaml` names the prompts to turn off: `push_publish: off` for the push guard's first-push prompt, and `secrets_env: off` for the credentials guard's `secrets.env` prompt. Clones with no local config keep every prompt. Switching a prompt off does not approve the command. The guard makes no permission decision and leaves a note naming the setting, and Claude Code's own permission settings then decide the command. In Claude Code's default permission mode, add a native allow rule as well, or Claude Code prompts instead. `push_publish` is deliberately narrow. The whole command must be one bare `git push`, or `git -C <path> push`, updating the current branch. The repository's push config must not remap the branch. And every push URL must name the public repository declared under `github:` in the same file. Everything else still asks: any compound command (including `git push … && gh pr create …`), a push to another remote, URL or path, a push after origin was re-pointed, a `gh pr create` that would push on its own, a force push, and a re-push to a branch with no open PR. Every hard block, and the deny a dispatched session gets, are out of reach. The key set is closed. A misspelled key, a duplicate key, a value that is not a boolean, or an unreadable file keeps the prompt, and the prompt says why. The setting is read from the file; there is no supported environment-variable override. Until the separate refspec fix lands, `git push -u origin HEAD` still prompts even with the setting off.
