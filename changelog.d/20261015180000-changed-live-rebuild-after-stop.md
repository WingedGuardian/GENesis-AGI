- On the `live` integration branch, `scripts/update.sh` now rebuilds `live` after it stops the server, in the place a merge takes on `main`, instead of before the stop. The rebuild therefore runs under the same safeguards as a merge: one database snapshot, the same in-progress record, and the normal rollback. If the rebuild refuses, fails or is interrupted, the old `live` tip (with its git hooks) is put back and the services restart on it; previously an interrupt or a failed stop could leave a moved `live` with only a message to re-run. Each update on `live` stays down a few seconds longer while the rebuild runs, and exit code 4 (a hand-edited systemd unit) can now follow a stop on `live`, when the refused unit is one only the rebuilt tip brings. That exit 4 also records the run as rolled back in the update history, which the pre-stop exit 4 on `main` does not; a rollback that does not complete exits 1.
