- **A `live` checkout that an interrupted update left half-written can now be put back with one command.** `scripts/deploy_candidates repair-move` returns every path the interrupted move touched to the code that ran before the update, then clears the update's restart guard once the shared check agrees. It never moves forward onto code that was never installed. Before changing anything it copies every file it will change to `~/.genesis/deploy-backups/<time>-live-move-repair/`, and any file that was not the update's own (another session's edit, a staged or flagged entry) is reported with the exact command that puts it back (staged content, both index flags, symlinks and FIFOs included; a socket, which holds nothing to save, is reported as removed), in the command's output, an alert and the deploy-health report, until it is re-applied or dismissed with `repair-move --dismiss <time>`. It also keeps a byte copy of git's index, and rebuilds an index a power loss tore from the code that ran before the update. A repair that was itself interrupted is reported unresolved only while the checkout is still half-written. `repair-move --explain` prints the manual steps. Every message about a `live` checkout left half-written at the code that ran before the update (bootstrap, `update.sh`, the live engine and the dashboard) now names the command; a `main` checkout's message is unchanged, and so is the one for an interrupted rollback, which this command does not yet finish. The command runs a copy of the repair installed outside the checkout, which a later change installs; until then it says the copy is missing, and `repair-move --explain` and the half-written-checkout message still give the manual steps. The rebuild also now writes its merge objects to disk durably, so a power loss right after it cannot lose the code the update was moving to.
