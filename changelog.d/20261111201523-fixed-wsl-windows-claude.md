- **On WSL, Genesis no longer mistakes the Windows Claude Code for its own.** WSL puts the Windows PATH into every Linux shell, so when Claude Code was installed on Windows but not inside the distro, Genesis found the Windows copy (`/mnt/c/.../AppData/Roaming/npm/claude`), installed no Linux copy, wrote the Windows directory into every service's PATH, and registered its MCP servers (and offered the login) against the Windows Claude Code. On a version mismatch it would also have run `npm install` against the Windows npm directory, and the shadow-copy cleanup could remove a working Linux copy in favour of the Windows one. A copy on a Windows drive mount is now ignored everywhere Genesis decides which Claude Code is its own, so install, bootstrap and update install the pinned Linux Claude Code instead — into `~/.npm-global` when there is no way to use sudo without a password prompt — and bootstrap warns when no Linux copy ends up installed. Run `scripts/update.sh` (or `scripts/bootstrap.sh`) on an affected install. MCP entries already written into the Windows user's `~/.claude.json` are not removed automatically; remove them from Windows with `claude mcp remove <name> -s user` if you do not want them there.
