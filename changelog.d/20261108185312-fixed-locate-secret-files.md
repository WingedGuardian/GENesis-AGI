- **`locate` no longer returns lines from credential files.** A content search (`contains`) over the repo used to search `secrets.env`, its backups, `.env` files, private keys and token files like any other file and return the matching lines, which in those files are the secrets themselves. Content search now skips any file the dashboard's file routes already treat as a credential (the predicate moved to `genesis.security.credential_names` and is shared), anything under a `.config` directory, and the configured secrets file under any name (matched by inode). Those files stay findable by name, and the response counts them in `content_skipped_credential_files`. A matched line anywhere else that contains a secret value from the secrets file (read as the runtime reads it; values under secret-named keys, or random-looking ones, not ordinary settings such as URLs or model names), for example a copy under another name or a pasted value, is withheld and counted in `content_redacted_secret_lines`, so neither case reads as "no match". Stored credentials are read through `reference_lookup`, which audits each read.
