- **`locate` no longer returns credential content from a content search.** A content search (`contains`) used to search `secrets.env`, its backups, `.env` files, private keys and token files like any other file and return the matching lines, which in those files are the secrets themselves. Content search now skips: any file the dashboard's file routes treat as a credential (that predicate moved to `genesis.security.credential_names` and is shared); untracked files with further credential names (`secrets.yaml`, `api_key.txt`, `*.tfvars`, editor backups of credential files, and similar); anything under `.config`, `.ssh`, `.aws`, `.docker`, `.gnupg` or `.kube`; the configured secrets file under any name (by inode); and any file whose content carries a secret value from the secrets file, such as a copy or a pasted value, including a line of a multiline key. Whole files are skipped, never single lines, so the result does not depend on the pattern. Skipped files stay findable by name and are counted in `content_skipped_credential_files`. Stored credentials are read through `reference_lookup`, which audits each read.
