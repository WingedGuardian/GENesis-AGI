- The disk guardian no longer sends an EMERGENCY "cgroup OOM kill" page when a job started with `python -m genesis.hostmetrics run` is killed by its own memory cap: the runner already tells whoever launched it ("killed at its memory cap (raise --ram)"). The guardian now reads the journal message systemd writes for every OOM-killed process, so a kill inside a capped scope that survives it is recognised, and the echo lines a systemd reload writes for slices are ignored. A kill anywhere else still pages. Each event in `~/.genesis/logs/oom_events.log` now also records which unit was killed, or that none could be named.
