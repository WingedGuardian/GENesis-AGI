- **The worktree guard refuses a removal whose worktree it cannot read.** Every direct `git worktree remove` is meant to be refused, but the guard only acted when it could read the worktree being removed. It now also refuses when `xargs` or `parallel` runs the removal (or `git worktree` with no operation) without naming the worktree, when the command pipes or here-strings the removal into a shell or `source`, and when a command it cannot tokenize, or a carrier such as `eval`, names the removal with no worktree after it. These refusals name no target, and each gives the remedy for text that is not a command. Measured over one install's recorded commands that mention worktrees (29,556, 2026-09-29): the same 177 refusals as before, with no new refusal and nothing that was refused before now running. One known cost: prose inside a here-document that names the removal under `xargs` is refused, because it cannot be told from a script a shell runs; write such text to a file instead.
