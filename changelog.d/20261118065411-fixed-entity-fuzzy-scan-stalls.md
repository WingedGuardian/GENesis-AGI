- **The hourly entity sweep no longer stalls other database queries for minutes.** Its fuzzy name matching, and the same matching when a new entity is resolved, now skips pairs whose cheap upper bounds already rule out a match before running the full comparison. The matches found are identical; the CPU spent is about 8x lower. The scan runs in a thread that holds the interpreter lock, so on a large entity registry every other query's row fetches had been waiting behind it (a 200-entity slice against about 41,000 names: 356 s down to 43 s on one core).
