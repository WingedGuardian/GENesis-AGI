- **Genesis can pay with a vault card after your Telegram tap (off by default).** With `card_fill.enabled: true` in `config/payments.yaml` (and the browser restarted), the new `browser_fill_card` tool reopens the checkout in a separate, short-lived browser window that no other browser tool can reach and that shows blank on the display, fills the merchant's other fields (email, address and similar), asks you to approve with a tap that shows the site, amount, card, Pay button label and the names of the fields it fills, then fills the card, clicks Pay itself and closes the window. It refuses a checkout or card form not served over https from a named site (an IP address or a local host is refused), and right before clicking Pay it checks that the page still shows what you approved and that every card field still holds what it typed. Genesis only ever sees a fixed status: after Pay it is `submitted_unverified`, or `challenge` / `card_url_blocked` / `card_url_leaked` / `pay_click_unknown` / `outcome_unknown` with "do NOT retry" (`card_url_blocked`: the window blocked a request that would have put a card value (number, expiry, CVC, name or postal code) in a URL; `card_url_leaked`: a redirect carried it, which the window can see but not stop; if either happens while the card is being typed, Pay is not clicked and the code is `card_url_before_pay`; if the checkout navigates or opens a window by itself while the card is being typed, Pay is not clicked and the code is `moved_while_filling`; both also say "do NOT retry"); a bank (3DS) check is not shown yet, so it closes the window and reports the outcome as unknown. While card fill is on, Camoufox keeps no form history, autofill, password capture, browsing history or disk cache for any site, and exposes no accessibility tree (other programs on the machine cannot read typed card numbers through it). Card and Pay selectors must be plain CSS.
