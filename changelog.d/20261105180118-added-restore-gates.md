- **`repair-move --restore <time> --check` now refuses a report it did not write before judging it.** The report folder and everything in it must belong to this account with no group or world write, reached without following a link; a report holding a path nested below another saved path is refused, one written before the integrity record is judged with a note that a restore refuses it, and no git call runs the repository's own fsmonitor program or hooks. `--restore` without `--check` still writes nothing. A newer report whose rows do not all name a plain path also refuses the check, since such a row could hide an overlap, and a row field holding a list or object is refused as a bad report rather than crashing the check. A saved directory holding a nested checkout's `.git` files (or a socket inside one) is now judged instead of refused whole, and `repair-move --wait N --restore TS --check` takes the mode after `--wait` and refuses two modes at once.
