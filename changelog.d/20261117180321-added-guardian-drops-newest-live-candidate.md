- On a `live` checkout, the Guardian's code-revert recovery now proposes dropping the newest deploy candidate (named in the approval prompt), runs the engine's own drop once you approve, and restarts the server only after the engine confirms the candidate is gone. While an update, rebuild or validation holds the update lock it runs no recovery at all: it tells you it is waiting, diagnoses again as soon as the lock is free, and alerts you again every 2 hours if the lock stays held. A lock it cannot read counts as held, unless the container is stopped; if it cannot read the lock for 2 hours, it asks for your approval instead of waiting on. Its diagnosis now sees the candidate list with added dates. Adding a candidate again at a new head moves it to the end of the manifest, so the last listed is the newest code.
