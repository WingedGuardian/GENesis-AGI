- On a `live` checkout, the Guardian's code-revert recovery now proposes dropping the newest deploy candidate (named in the approval prompt), runs the engine's own drop once you approve, and restarts the server only after the engine confirms the candidate is gone. While an update, rebuild or validation holds the update lock it restarts nothing: it tells you it is waiting and diagnoses again as soon as the lock is free. Its diagnosis now sees the candidate list with added dates. Adding a candidate again at a new head moves it to the end of the manifest, so the last listed is the newest code.
