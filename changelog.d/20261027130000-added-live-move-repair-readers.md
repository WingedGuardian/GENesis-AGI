- **The deploy-health report now lists what the live-move repair saved until it is put back.** Each path the repair saved that was not the update's appears as `live_repair_saved:<n>` with its exact re-apply step, until that step would change nothing or the report is marked handled with `repair-move --dismiss <time>`. A step is offered only while running it would lose nothing: the checkout is still on the repair's commit, the path still holds what the repair left there or what the step puts back, and every staged entry the step removes below the path still holds what the repair left there or nothing. Once someone has written the path since, or the checkout has moved on, the step is withdrawn and one line per repair says how many saved paths are no longer re-applicable and where their copies are. The step shown is always rebuilt from the repair's own rules, never copied from the report file, and a report row with an unsafe or malformed field is skipped and counted as `live_repair_malformed:<n>` until its report is dismissed. An interrupted repair reads as unresolved only while the shared restart guard still calls the checkout half-written. The awareness check words both findings itself and never pages for them. The host guardian's diagnosis now picks the newest eligible repair report inside the container, so newer dismissed or superseded reports can no longer hide it, and a report over the size cap is shown as too large instead of skipped. Every reader reads a report through one loader that refuses a report it cannot read safely (a name, file type, size or row count the repair never writes, or another checkout's report) and counts it as malformed; every shown step is printable text that runs exactly, even for a file name that is not valid UTF-8; and the open health endpoint shows only the counts to a caller without credentials.
