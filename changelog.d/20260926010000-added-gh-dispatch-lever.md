- **A background session can no longer be given a shell-capable GitHub grant by accident.** One dispatch profile is allowed to run the `gh` CLI, and it had never actually run — which, it turns out, was the only thing keeping it inert. Creating a campaign row naming that profile passed validation, the campaign runner hands the row's profile straight to the spawner, and the ego honours a model-authored profile from its own execution brief on the same basis. So one row, or one proposal, was the entire distance between dormant and running. That is now a decision instead of an oversight: a dispatch is refused unless an operator has armed it, with a refusal that names the file to edit and the value to set rather than saying "disabled by config".
- **One predicate, three callers, because a refusal is permanent and callers retry.** The spawner raises on it — that is the boundary, and it sits at the one method every dispatch path funnels through, which is also the only place a Bash allowlist is attached, so the capability cannot be picked up by a route that bypasses it. Campaign creation consults the same predicate so an operator gets the answer where they asked the question; without that the campaign is created "successfully" and then fails on every cron tick, which is observable in job health but is a poor way to learn. And the ego's profile selection consults it too, because a refusal lasts until someone edits config while the failed-dispatch path returns the proposal to approved with no attempt counter — honouring a refused name would have re-dispatched and re-failed once per sweep, indefinitely, on a path nobody watches.
- **Keyed on the capability, not on the profile's name.** It asks whether the requested profile's allowlist contains the tool, so an install that grants the same shell to a profile of its own through the documented profile-overlay hook is covered by construction rather than by someone remembering a registry entry — the overlay writes into the very table the predicate reads. A name-keyed version passes every other test of this change, which is why that difference has its own test and its own mutation in the verification sweep. The scope is stated precisely rather than generously: a profile that *declares* the tool cannot be dispatched unarmed, and a profile with an unrestricted shell and no declaration is not gated at all — the allowlist restricts a shell, it never grants one.
- **Filesystem reads are denied on that profile.** Writes were blocked and reads were not, while permissions prompts are skipped and an outbound notification tool is available — so attacker-authored pull-request text could have had the session read an owner-readable credential file and send it onward. No environment setting closes that; the tool scope is what closes it. Found by an adversarial review of this change.
- **What arming grants is an install question, and nothing here claims to know the answer.** An earlier draft of this change told the session it held no credential. That was false on the branch it was written on — removing the credential from the sealed configuration is a separate change on its own timeline — so an operator would have armed this believing the blast radius was public reads when it was the owner's full account, on the one profile whose input is authored by strangers. Every operator-facing text now carries the one command that settles it on the reader's own install, the session's instructions cover both outcomes without asserting either, and a test fails if any of them starts asserting a posture again. Worth knowing either way: the tool requires authentication even to read, so an unauthenticated armed session cannot do the profile's job at all.
- **Ships off, and every damage path degrades to off.** The master switch, an unknown value, a wrong type, an explicit null, and the boolean that a hand-edited unquoted `off` becomes under YAML 1.1 — a sibling config ships exactly that form, so it is a likely copy. That last case degrades silently, because it is a reasonable hand-edit that means what the operator intended, while a genuine typo warns; a verification sweep caught that the two were indistinguishable to the tests, since both merely returned off, and the diagnostic is what the branch buys. The master switch requires a real boolean: a truthiness test there was a measured fail-open, because the quoted spelling this file's own comments encourage is a non-empty string, and it left the lever live while the operator believed they had switched it off. Config is read fresh per dispatch, so arming takes effect on the next one with no restart, and an environment kill switch forces off regardless of the file.
