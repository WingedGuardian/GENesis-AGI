- **The contributor-review workflow now posts its review request under a maintainer identity.** The automated reviewer resolves who asked from the comment author and refuses a request authored by `github-actions[bot]`, so every request this workflow posted was rejected in seconds without the diff being read — the request had never once succeeded. The request is now sent by a separate step holding a fine-grained `REVIEW_REQUEST_TOKEN`; the step that decides eligibility keeps the default token, which drops to read-only. An unset secret warns and posts nothing rather than falling back to the identity the reviewer rejects, and an expired one fails the job with the reason instead of throwing. Both `github-script` steps are pinned to a commit SHA rather than a mutable tag. A new test asserts these properties across every job in the file, including that no job checks out head code, runs a shell step, or interpolates an expression into a `github-script` body — the property that separates an outside author from a privileged credential in a `pull_request_target` run.
