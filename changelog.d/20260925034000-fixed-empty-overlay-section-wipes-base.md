- **A half-finished edit to your local routing overlay no longer takes routing offline.** If `model_routing.local.yaml` contained a key with nothing under it — a bare `providers:`, or a call site whose id you typed before writing its body — YAML read it as *nothing at all* rather than as *no overrides*, and it replaced whatever the shipped config held there instead of adding to it. Depending on which key it was, that removed every provider, removed every call site, or produced an error while the configuration was being read. In each case Genesis still started and every model call site was dark, with one log line as the only sign, and nothing wrong in the file to explain it. Overrides are now merged so that an empty or malformed value can never replace a section the shipped config defines, at any level; the unusable part is reported by name and ignored, and it is also cleared out of your overlay the next time the dashboard saves, so it does not sit there being silently ignored. Editing a call site through the dashboard while the file was in that state used to fail with a server error and no backup written — that path now saves normally. Overrides that are valid are applied exactly as before, including ones for keys the shipped config does not define.
