- **A browser tab can now be armed as a payment tab, ready for the card-fill flow (#3172).** No caller arms one yet. Arming waits for any browser tool action already running on the tab. While a tab is armed, its page snapshots hide every text field, number field and dropdown value. Text on any page that matches a filled value is hidden too, including respaced or reformatted forms such as `12 / 34`, a month-name expiry or a partly typed card number; matching is by keyed hash, and the values themselves are never kept. Every tool result and error is checked the same way. `browser_run_js` is refused in the whole browser. The armed tab, and any popup it opens, refuses screenshots, typing, uploads and navigation. `browser_press_key` takes only Enter, Tab, Shift+Tab and Escape there. A click takes only a plain CSS selector, reports URLs without their query strings, and reports errors as fixed text. Log lines keep their text but drop their arguments and tracebacks, and the Turnstile debug log writes nothing. The armed page draws nothing on screen, including after Back: no fields, text, canvas or shadow-DOM content. The payment flow ends by closing the tab and its popups and clearing their sites' storage: local storage, IndexedDB, caches, the origin-private file system and service workers. If a write to the crash-recovery file fails after a fill, the tab is closed and cleared at once. Until a site's clear succeeds, pages on that site are not snapshotted or screenshotted, and the Camoufox profile is not backed up. Any `browser_run_js`, or any navigation to a non-http(s) URL, since Camoufox started marks the browser as unfit for card entry until it restarts. With `card_fill.enabled` set in `config/payments.yaml` (off by default; `GENESIS_CARD_FILL_DISABLED=1` wins, and is read again at every arming), Camoufox launches with these turned off: form history, autofill, session-store form data, closed-tab undo, select-to-copy, crash restore, password capture, history and the disk cache.
