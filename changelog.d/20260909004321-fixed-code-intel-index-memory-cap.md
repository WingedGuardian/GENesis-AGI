- **Code intelligence indexing no longer gets killed partway through.** The memory cap on the indexing job was set below what indexing this codebase actually needs, so the job was repeatedly killed and the index never completed. The cap now comes from a measurement of the real peak, bounded by the machine's own memory limit so that on a small install it still contains the job rather than matching the whole container. The job is also marked as the first thing the system should sacrifice if memory does run short — ranked below Claude Code's own subprocesses — so a shortage costs an index rather than your session or the server.
