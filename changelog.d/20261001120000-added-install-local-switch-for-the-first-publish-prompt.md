- **An install can now switch off the first-push prompt for its public repo, in its plainest form only.** Set `hooks.asks.push_publish: off` in `~/.genesis/config/genesis.yaml`. The push guard then stops asking for the first `git push` of the current branch when all of these hold: the push is a plain one (no `-c`, no environment prefix, no extra refspecs, nothing but inert steps beside it); the remote git really pushes to resolves, after any URL rewrite, to exactly `https://github.com/<owner>/<repo>` for the public repo configured under `github.user` / `github.public_repo` (ssh and scp forms always ask); its push config is simple; no `http.*` git config, remote proxy or remote helper is set; and no proxy, TLS-trust, ssh-program or git-config-injection environment variable is visible to the hook. Known limit: the hook cannot see variables exported only in a shell profile. Like the `secrets_env` switch, it approves nothing: the guard makes no permission decision and leaves a note naming the setting. `gh pr create` is not covered, because without a terminal gh refuses to push an unpushed branch rather than pushing it. Everything else still asks or blocks as before, including force pushes, pushes anywhere else, compound commands, close-then-push, re-pushes with no open PR, and round-cap asks. A dispatched session is still denied. Clones with no local config keep the prompt. This replaces the earlier note that `push_publish: off` is ignored.
- **Fixed: a bare `git push` is now checked against the remote git actually pushes to.** When `branch.<name>.remote` named a remote other than origin and its remote-tracking ref was missing, the guard assumed origin. A re-push could then be allowed silently on the strength of origin while the push went to the other remote. The guard now reads `branch.<name>.remote` from config, and an unreadable value asks.
