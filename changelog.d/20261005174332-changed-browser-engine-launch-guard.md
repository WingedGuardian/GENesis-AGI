- **Browser tools no longer download a browser engine mid-call.** Before launching Camoufox, the browser tools now check, by reading files only, that the package and the engine camoufox would select are installed and supported by the installed playwright; if not, they say what is missing and how to install it, instead of letting the launch delete an old engine and download a new one inside the tool call. Every local browser (the MCP tools, the Medium publisher and `scripts/browser.py`) holds a shared browser-stack lock for as long as its process may be alive, including across a stale-browser restart and after a close that did not finish, so a browser-stack upgrade cannot start under it and a launch during an upgrade is refused with a message. When the browser packages change on disk after a Claude Code session has already loaded them, the navigate error says to restart the session rather than reinstall. A new `browser_automation` capability reports whether the Camoufox package and its engine are ready. Process detection now also covers patchright's driver.
