- **A broken `model_routing.local.yaml` no longer takes every model call site offline.** Most mistakes in that file used to stop the router from starting: a key with nothing under it, a value of the wrong type, or a retry profile name that was misspelled or had no body. Genesis still came up, but no model call site could route, and the only sign was one log line. Invalid YAML was ignored with only a warning. Now, whenever the overlay cannot be used, Genesis logs an error, records a health observation that shows on the dashboard, and routes on the shipped config without the overlay's overrides until you fix it. Every restriction the overlay makes still applies during that fallback, so the fallback never allows a call, provider, attempt or spend that your file ruled out. A provider you disabled or marked not free stays that way. The lower `rpd_limit`, `tpd_limit` and `rpm_limit` apply. `never_pays` holds. `dispatch: api` and `dispatch: cli` keep a `dual` call site on that one executor. Where your file and the shipped config leave a call site no executor in common, it is blocked: it stays listed as API-only with no providers, so it runs nothing and is not treated as a provider outage. A narrowed chain stays narrowed and in your order. The lower retry `max_retries` and `max_total_s` apply, including through a call site moved to a tighter retry profile. A provider whose model, type, endpoint, profile or params you changed is left out, because the shipped values are not the ones you run. Settings that limit nothing, such as backoff pacing or how long a tripped provider rests, are set aside with the rest of the file. Old provider names from before a rename are read the same way the normal load reads them. Where the file names a provider, call site or retry profile but the value there cannot be read, Genesis reads it the restrictive way: the provider is disabled, the call site is blocked, and `max_retries` is 0. A retry deadline that cannot be read keeps the shipped one, because a deadline of 0 would stop the call site entirely. If the file cannot be parsed at all, nothing can be read from it, and the fallback runs on the shipped config as it is. A bare `call_sites:` header is handled the same way; it used to remove every call site silently. Some values used to load and then fail on every call: text or NaN where a number belongs, or `"false"` in quotes for `free`, `default_paid` or `never_pays`. These are now rejected at load time and trigger the same fallback. A `null` on `free`, `default_paid`, `never_pays` or `retry_profile` resets that field to its default. `enabled` keeps its existing rules: strings such as `"false"`, and empty values, mean off. The dashboard's **Reload routing config** button, and a call-site save with nothing to change, now refuse a broken overlay and keep the running config, and the routing editor shows the dispatch mode the running router actually uses. Saving a call site from the dashboard checks the exact file it is about to write, and refuses any save the next restart would reject. It also refuses to overwrite an overlay file it cannot read. It can still replace a malformed chain on the call site being saved. Separately, an API-only call site whose providers are all disabled now stays listed as blocked, with a warning. It used to be dropped, and the autonomous dispatcher then treated it as `dual`, which could escalate it to a Claude Code session.
