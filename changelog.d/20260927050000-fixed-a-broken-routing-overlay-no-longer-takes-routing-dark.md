- **A broken `model_routing.local.yaml` no longer takes every model call site offline.** Most mistakes in that file used to stop the router from starting: a key with nothing under it, a value of the wrong type, or a retry profile name that was misspelled or had no body. Genesis still came up, but no model call site could route, and the only sign was one log line. Invalid YAML was ignored with only a warning. Now, whenever the overlay cannot be used, Genesis logs an error, records a health observation that shows on the dashboard, and routes on the shipped config without the overlay until you fix it. A bare `call_sites:` header is handled the same way; it used to remove every call site silently. Some values used to load and then fail on every call: text or NaN where a number belongs, or `"false"` in quotes for `free`, `default_paid` or `never_pays`. These are now rejected at load time and trigger the same fallback. A `null` on `free`, `default_paid`, `never_pays` or `retry_profile` resets that field to its default. `enabled` keeps its existing rules: strings such as `"false"`, and empty values, mean off. The dashboard's **Reload routing config** button now refuses a broken overlay and keeps the running config. Saving a call site from the dashboard checks the exact file it is about to write, and refuses any save the next restart would reject. It also refuses to overwrite an overlay file it cannot read.
