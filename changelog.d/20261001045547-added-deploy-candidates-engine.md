- **`scripts/deploy_candidates`: the engine for `live`, a local integration branch that runs unmerged pull requests on the install (inactive for now).** `live` is origin/main plus the candidate branches listed in `~/.genesis/deploy_manifest.json`, rebuilt from scratch without touching the working tree (`git merge-tree` and `git commit-tree`), so several open PRs can run together while they are reviewed. `rebuild` excludes a candidate that conflicts or fails admission, by name and reason, along with any candidate that carries its unmerged commits; it skips a candidate that adds nothing beyond what is already merged in; it retires a candidate once its PR shows as merged on GitHub, and retires nothing when GitHub cannot be read; it refuses a dirty checkout, a commit on `live` that it did not make, and a `live` checked out in another worktree; it moves the checkout once, and only when the files change; and it fast-forwards local `main`. It never restarts the server. `drop`, `list` and `status` work from a plain shell (`env -i`), so a candidate that breaks the session hooks can still be taken out; a `drop` that cannot rebuild changes nothing. `adopt` saves uncommitted edits in the checkout as a new branch and reports, file by file, whether each edit matches origin/main, matches an open PR's head, or neither. Admission refuses database and data migrations, the boot-time schema files, the host guardian's own files, the Claude Code pin and the nightly host aligner. A dispatched session's candidate, or a Devin-authored PR, needs `--owner-approved`. **Nothing can go live yet:** `add` requires the server to be running the change that makes `update.sh`, crash recovery and the guardian's code revert rebuild `live` instead of overwriting it, and that change has not merged.
