- **The push guard now recognises `git push -u origin HEAD` as a push of the current branch.** It used to recognise only the bare branch name, so `HEAD`, its alias `@`, `refs/heads/<branch>` and `HEAD:refs/heads/<branch>` fell to the generic "approve this push" prompt. For those spellings a re-push of an already-published branch prompted every time, and the checks that report a public branch with no open PR, or a push that follows a `gh pr close` in the same command, never ran. They run now. A first push still asks, and a push naming another branch, a tag, or `main` from a feature branch keeps asking as before. The branch-name spellings also keep asking when the repository's push config (`remote.<name>.push`, `push.default=upstream`) would send the push to a different branch. That now includes the plain `git push origin <branch>`, which previously got no such check.
